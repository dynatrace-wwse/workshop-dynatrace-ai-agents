    3. Platform install#

    With the cluster running (module 2), meet the observability + agent platform. The manifests live under cluster/; the installers are functions in .devcontainer/util/my_functions.sh.

    What gets installed

    Dynatrace Operator (Kubernetes monitoring), OpenTelemetry Operator + a gateway collector, kagent (clean base — no agents yet), Tetragon (eBPF security), an Agent Sandbox isolation baseline, and Phoenix (LLM eval/trace UI).

    1. What is already installed#

    Your environment's post-create step ran installPlatform, which installs, in order:

    Component How Namespace
    Dynatrace Operator + DynaKube (Kubernetes monitoring, ActiveGate only) framework dynatraceDeployOperator + deployDynatrace k8s-only dynatrace
    OpenTelemetry Operator + gateway collector Helm + cluster/otel/collector-gateway.yaml opentelemetry-operator-system
    Phoenix cluster/phoenix/phoenix.yaml, published as app phoenix phoenix
    kagent (clean base — no agents yet) OCI Helm chart, published as app kagent kagent
    Tetragon Helm tetragon
    Agent Sandbox baseline cluster/agent-sandbox/isolation.yaml agent-sandbox
    LLM backend DeepSeek secret, or Ollama when no key is set kagent / ollama

    Every piece is idempotent, so you can re-run any of them — or the whole thing:

    installPlatform        # everything above
installOtelGateway     # or one component at a time

    2. Verify the platform#

    kubectl get pods -A                                   # everything Running
kubectl get dynakube -n dynatrace                     # Dynatrace k8s monitoring
kubectl get otelcol -n opentelemetry-operator-system  # gateway collector
kubectl -n kagent get pods                            # kagent controller / ui / kmcp
kubectl -n phoenix get pods                           # Phoenix
listApps                                              # kagent + phoenix URLs

    How telemetry flows#

    flowchart TD
    src["kagent agents / instrumented workloads"] -->|OTLP 4317/4318| gw["otel-gateway-collector<br/>(ns opentelemetry-operator-system)"]
    gw -->|observe| dt["Dynatrace tenant (OTLP ingest)"]
    gw -->|eval / trace UI| phx["Phoenix :4317"]

    The gateway normalises OpenInference/Traceloop LLM attributes to OpenTelemetry gen_ai.* semconv so Dynatrace and Phoenix agree on names. There are no agents yet — kagent is a clean base; module 4 deploys the SRE agent and the BMAD crew, at which point spans start landing in both backends.

    BindPlane

    BindPlane (OTel collector management) is illustrated, not installed — see the walkthrough.

    Troubleshooting#

    • Tetragon not Ready — eBPF/BTF on the container node's kernel; see cluster/tetragon/README.md.
    • OTel operator hangs — it must use its self-signed webhook cert (autoGenerateCert), already set in otel/operator-values.yaml.
    • No data in Dynatrace — check kubectl -n opentelemetry-operator-system logs deploy/otel-gateway-collector; the ingest token needs openTelemetryTrace.ingest, metrics.ingest, logs.ingest.
